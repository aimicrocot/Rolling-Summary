# Rolling Summary

Расширение для [SillyTavern](https://github.com/SillyTavern/SillyTavern), которое поддерживает единый **running summary** текущего чата. Периодически собирает сообщения в единый связный саммари, содержащий основную суть происходящего в разговоре. Саммари хранится отдельно от сообщений чата и может использоваться моделью при дальнейшем продолжении разговора.

## Особенности

* Единый общий summary.
* Пользователь сам задаёт максимальный размер summary в токенах.
* Поддерживается ручной запуск саммаризации.
* Поддерживается автоматическая саммаризация через заданный интервал сообщений.
* Для саммаризации можно использовать отдельную модель/API.
* Summary хранится в `chat_metadata` и не добавляется непосредственно в текст сообщений.
* Старые сообщения могут быть скрыты из контекста после их саммаризации, при этом их содержание остаётся доступным через summary.
* При каждом обновлении модель получает существующий summary и новые сообщения и создаёт обновлённую версию summary.
* Если summary становится слишком большим, модель получает инструкцию переписать его так, чтобы итоговый текст уложился в заданный пользователем лимит.

## Зачем это нужно

В SillyTavern уже существует функциональность Summarize, однако у неё есть ограничения для некоторых сценариев использования. В частности, бывает полезно использовать для саммаризации отдельную, более дешёвую модель, не расходуя ресурсы основной модели, которая используется для генерации ответов. Это расширение построено именно вокруг такого сценария.

Например:

```text
Основная модель
    ↓
Генерирует ответы персонажа

Дешёвая модель для summary
    ↓
Периодически обновляет running summary
```

Таким образом, большая и дорогая модель может использоваться исключительно для генерации самого диалога, а компактная модель — для поддержания контекста.

## Как работает summary

Расширение использует единый изменяемый текст:

```text
Текущий summary
        +
Новые сообщения
        ↓
     Модель
        ↓
Обновлённый summary
```

Например, после нескольких сообщений summary может выглядеть примерно так:

```text
Алекс и Мира находятся в старом доме за городом. Они приехали туда
после получения загадочного письма. Мира подозревает, что письмо
связано с исчезновением её брата. В доме они обнаружили запертую
комнату на втором этаже, однако пока не нашли способ её открыть.
Между Алексом и Мирой сохраняется напряжённость из-за того, что
Алекс не рассказал ей о своей предыдущей встрече с отправителем
письма.
```

После появления новых сообщений старый summary не сохраняется как отдельный элемент. Вместо этого модель получает его вместе с новыми сообщениями и создаёт новую объединённую версию:

```text
Старый summary
       +
Новые сообщения
       ↓
Новый summary
```

Это позволяет поддерживать относительно небольшой объём постоянного контекста даже в очень длинных чатах.

## Лимит summary

Размер итогового summary задаётся пользователем в токенах.

Например:

```text
Summary token limit: 1000
```

Это означает, что расширение просит модель поддерживать итоговый summary примерно в пределах 1000 токенов. Для оценки размера используется приблизительное соотношение количества символов к количеству токенов, а не полноценный tokenizer. Поэтому значение является ориентировочным. При обновлении summary модель получает инструкцию сохранить наиболее важную информацию и уложить итоговый текст в заданный пользователем лимит.

Важно: лимит относится именно к **итоговому summary**, а не к размеру входного запроса.

## Обработка новых сообщений

Расширение отслеживает позицию последнего обработанного сообщения.

При следующем запуске саммаризации берутся сообщения, появившиеся после последнего сканирования:

```text
[уже обработанные сообщения]
[уже обработанные сообщения]
[новые сообщения] ← отправляются на summary
```

Новые сообщения передаются модели одним запросом.

Специального ограничения вроде:

* максимум N сообщений;
* максимум N символов;
* разбиения на несколько партий

нет.

Это сделано намеренно: расширение не вводит искусственный лимит на размер одной операции саммаризации. При этом очень большой объём новых сообщений может привести к большому prompt и, соответственно, упереться в контекстное окно используемой модели.

## Автоматическая саммаризация

Помимо ручного запуска, можно включить автоматическую саммаризацию. Пользователь задаёт интервал, после которого расширение обновляет summary.

Например:

```text
Auto summary: ON
Interval: 20 messages
```

После появления необходимого количества новых сообщений расширение автоматически запускает обновление summary. Автоматическая саммаризация работает независимо от того, какая модель используется для обычной генерации ответа.

## Отдельная модель для summary

Одно из основных назначений расширения — возможность использовать для summary отдельный API/model provider.

Например:

```text
Основная модель:
GPT / Claude / Gemini / другая модель

Summary model:
небольшая дешёвая модель
```

Это позволяет снизить стоимость и нагрузку при поддержании длинного контекста.  Summary-модель должна быть достаточно способна понимать предыдущий summary и новые сообщения и компактно пересказывать происходящее. Для API, совместимых с OpenAI API, может использоваться отдельный endpoint и соответствующие настройки подключения.

## Summary и сообщения чата

Summary не является сообщением пользователя или персонажа. Он хранится отдельно от истории сообщений и не должен появляться непосредственно внутри самих постов.

В результате история чата остаётся историей чата:

```text
User: ...
Character: ...
User: ...
Character: ...
```

а summary существует отдельно:

```text
Summary:
...
```

## Скрытие старых сообщений

Для уменьшения количества контекста расширение может скрывать сообщения, которые уже были включены в summary.

Схематично:

```text
Summary
│
├── информация из сообщений 1–20
│
└── информация из сообщений 21–40

Контекст модели:
├── Summary
├── сообщения после позиции 40
└── новые сообщения
```

При этом сами сообщения не удаляются из чата. Их содержимое просто перестаёт отправляться модели напрямую после того, как соответствующая информация была включена в summary. Это позволяет использовать расширение как механизм сжатия истории длинного разговора.

## Хранение данных

Состояние summary привязано к конкретному чату и хранится в его `chat_metadata`. Таким образом, summary не является глобальным для всех персонажей или чатов. Каждый чат имеет собственное состояние саммаризации.

В частности, расширению необходимо отслеживать как минимум:

* текущий summary;
* позицию, до которой сообщения были обработаны;
* настройки/состояние автоматической саммаризации.

## Отличие от Summary-Tracker

Это расширение является самостоятельным проектом, рождённое на базе [Summary-Tracker](https://github.com/aimicrocot/Summary-Tracker/).

Основное концептуальное отличие — формат результата. Summary-Tracker ориентирован на извлечение и хранение отдельных фактов.

Здесь используется другой подход:

```text
Summary-Tracker:

Сообщение 1 → факт
Сообщение 2 → факт
Сообщение 3 → факт
              ↓
          список фактов


Running Summary:

Сообщения 1–N
      ↓
  единый summary
```

То есть расширение пытается сохранить не каждый отдельный факт как самостоятельную запись, а целостное представление о текущем состоянии разговора.

## Отличие от встроенного Summarize

В SillyTavern существует встроенная функциональность Summarize.

Это расширение предназначено для другого сценария использования, в частности когда пользователю необходимо:

* самостоятельно выбрать модель для summary;
* использовать отдельную дешёвую модель;
* отделить генерацию ответов от генерации summary;
* контролировать максимальный размер итогового summary;
* поддерживать единый running summary.

Кроме того, расширение не предназначено для добавления summary непосредственно в содержимое сообщений чата.

## Установка

Установите расширение через механизм установки расширений SillyTavern или вручную добавьте репозиторий в каталог расширений.

Для ручной установки:

1. Откройте каталог расширений SillyTavern.
2. Клонируйте репозиторий расширения в каталог `third-party`.
3. Перезапустите SillyTavern.
4. Откройте настройки расширения.

Пример:

```bash
cd SillyTavern/public/scripts/extensions/third-party
git clone <REPOSITORY_URL>
```

Замените `<REPOSITORY_URL>` на URL репозитория этого расширения.

## Использование

После установки откройте настройки расширения.

Основной рабочий процесс выглядит следующим образом:

1. Настройте подключение к модели, которая будет использоваться для summary.
2. Укажите модель.
3. Установите максимальный размер summary в токенах.
4. При необходимости включите автоматическую саммаризацию.
5. Укажите интервал автоматического обновления.
6. Запустите саммаризацию вручную либо продолжайте разговор до срабатывания автоматического режима.

После первого запуска расширение создаст summary на основе доступной истории.

Последующие запуски будут обрабатывать только сообщения, появившиеся после предыдущего сканирования.

## Пример

Предположим, пользователь установил:

```text
Summary limit: 1500 tokens
Auto summary: enabled
Interval: 30 messages
```

После первых 30 сообщений:

```text
30 сообщений
     ↓
Summary model
     ↓
summary ≈ 1500 tokens
```

После следующих 30 сообщений:

```text
Существующий summary
        +
сообщения 31–60
        ↓
Summary model
        ↓
обновлённый summary ≈ 1500 tokens
```

При этом сообщения 1–30 могут быть скрыты из контекста, поскольку их существенная информация уже представлена в summary.

Следующее обновление будет работать с:

```text
обновлённый summary
        +
сообщения 61–90
```

и так далее.

## Важные ограничения

Расширение использует приблизительную оценку количества токенов по количеству символов. Это не точный tokenizer конкретной модели, поэтому установленный лимит следует воспринимать как ориентир.

Размер входного запроса для саммаризации специально не ограничивается. Если между двумя запусками накопилось очень большое количество сообщений, весь этот объём будет отправлен модели одним запросом.

Поэтому выбранная summary-модель должна иметь достаточно большое контекстное окно для предполагаемого размера чатов.

Также качество summary зависит от самой модели. Слишком маленькая или слабая модель может терять важные детали при каждом очередном переписывании summary.
